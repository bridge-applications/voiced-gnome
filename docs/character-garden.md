# Character garden

The default experience is a single-character conversation. Eighteen cast entries in `packages/types/src/characters.json` supply short titles, fictional histories, personalities, distinct outfits and a selection of male premade voices. Personal names are omitted from the interface and agent introductions. The full original garment catalog supplies the looks; eight combinations were added to the previous ten presets. The 18 characters use 13 male stock voices verified against ElevenLabs metadata; a few characters with similar personalities share a voice. All backstories use male pronouns. There are no extra garments in the current Pebbler source that needed importing.

One persistent WebGL canvas shows the large selected character and two smaller idle neighbouring previews, sharing the cached rig and textures. A fourth hidden Spine instance receives the incoming outfit before navigation begins. Each character then moves independently between positions, interpolating its size and position over 440 ms. The right arrow selects the right neighbour and moves the characters left; the left arrow selects the left neighbour and moves them right. The outgoing edge character becomes the hidden spare, and the incoming centre instance becomes the active speech and gesture rig. Arrows beneath the neighbouring previews wrap the cast. The identity shows only the character title, and there is no dropdown selector. Reduced motion changes positions immediately. Cancelling restores the previous positions. Browsing never starts a microphone or consumes generation credits. A failed outfit request preserves the prior character. Switching ends conversations, stops audio and body motion, and ignores stale callbacks.

Each character has a fixed `skinColorId` using Pebbler Telegram's eight-option palette. Dragon uses purple; the remaining cast uses the original and six natural tones. Tint is applied only to authored skin surfaces after animation updates; clothing, eyes, teeth and transparent speech mouths retain their original colors. The tone belongs to the Spine instance and follows it through carousel moves, including the entering spare. Neighbour previews use their own assigned tones. No extra textures or API calls are needed.

**About me** beside the character title plays a prerecorded introduction in that character's assigned male voice. Each introduction has two emotes aligned to phrases in the recording, and Rhubarb mouth cues derived from the actual MP3. The clip and cues load on demand, with no microphone request or live generation. Gesture timing follows media playback time, so buffering does not advance choreography. The button becomes Stop during loading/playback. Natural completion keeps the output graph connected for the measured audio-device latency plus a small scheduling margin before cleanup, so the final queued samples can reach the speakers. Explicit Stop and switching cancel immediately. Introduction text is hidden in the demo. Switching characters, starting a conversation, hiding the page, leaving the variant or pressing Escape disposes audio, requests and gesture state. The button is disabled during an active conversation. Reduced motion retains speech and facial articulation while suppressing body emotes.

The prompt stays below the character and accepts either a question or a story request. There is no script planner or multi-character cast in this variant. The character agent and on-demand typed speech use `eleven_v4_turbo`. Existing prerecorded introductions retain their original audio; future generation uses v4 Turbo. One authenticated ElevenLabs agent receives the selected personality and that character’s recent transcript as dynamic variables. Its voice and first message are overridden per selected character. History lives only in page memory, separately per character, with 40 retained messages and a bounded recent reconnect context; it is cleared on reload.

`POST /api/characters/session` accepts only a catalog character ID and returns a bounded, validated signed WebSocket URL plus the corresponding voice ID and session limit. Microphone sessions use ElevenLabs’ SDK streaming audio, input meter, output mute, interruption and alignment events. Text-only sessions never request microphone access; their replies are spoken through `POST /api/characters/speech` using the catalog voice and Eleven v4 Turbo Text to Dialogue with timestamps. Long replies are split at sentence/word boundaries into bounded chunks without truncating the transcript. Both endpoints retain origin checks, quotas, bounded request/response parsing and cancellation; the API key stays on the Worker.

The `perform_gesture` and `set_expression` client tools validate a shared allowlist and report a successful action only in the active conversation. All 19 emotes and the grand celebration can also be previewed locally. Reduced-motion preferences suppress body movement and sliding; expression feedback remains available. Escape, hiding the page, leaving this variant, ending a call or selecting another character stop the active call and audio.

The earlier story theatre and original wardrobe demo remain historical source prototypes. Their paid API routes are retired and their interfaces are excluded from the current app. See `anti-abuse.md` for the production access/session/quota flow and `validation.md` for checks performed.
